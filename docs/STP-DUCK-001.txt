1. INTRODUCTION
================================================================================

1.1 PURPOSE
This document defines the test plan for the Duck Chess game engine and RL
training pipeline. It describes what is tested, how it is tested, and what
constitutes acceptable quality before promotion to production checkpoints or
release.

1.2 SCOPE
The plan covers the pure Python game engine (DuckChess_Game/Logic/), the RL
interface layer (rl_mixin.py, action_masker.py, observation_encoder.py), the
atomic turn pipeline (move_pipeline.py), and the diagnostic/validation layer
(game_state_validator.py). The Pygame UI layer and SBThree training scripts
are explicitly OUT OF SCOPE for this test cycle.

1.3 OBJECTIVES
- Confirm correct implementation of all Duck Chess rules, including fowling,
  duck blocking, en passant, castling, and promotion.
- Verify correctness of the RL observation tensor (19 × 8 × 8) and action mask
  (4096-dimensional boolean array).
- Confirm 2D board and bitboard representations remain in sync throughout all
  legal operations.
- Verify that the MovePipeline enforces atomicity: illegal moves produce no
  state mutation.
- Establish a regression baseline for further training stages.

1.4 REFERENCES
- CLAUDE.md: Project documentation
- DuckChess_Game/Logic/logic.py: Game engine hub
- DuckChess_Game/Logic/rl_mixin.py: RL interface
- DuckChess_Game/SBThree/train_stage12.py: Training entry
- pytest.ini, tests/conftest.py: Test configuration

1.5 ASSUMPTIONS
- All tests run with Python 3.12 in the .venv virtual environment.
- Tests execute in headless mode (no Pygame window); game_mode='rl_training'
  is set by the HeadlessEngine fixture in conftest.py.
- No GPU is required; PyTorch CPU inference is sufficient.
- Network access is not required.

5. TEST STRATEGY & APPROACH
================================================================================

5.1 UNIT TESTING
All pure-logic classes (BitboardManager, RulesChecker, ActionMasker,
ObservationEncoder, GameStateValidator, MovePipeline) are tested in isolation
using pytest with conftest.py fixtures. Each test is stateless: a fresh
HeadlessEngine or component instance is constructed per test.

5.2 INTEGRATION TESTING
Key integration scenarios exercise the full engine stack end-to-end:
- A complete legal turn: piece move → duck placement → turn advance.
- En passant setup followed by legal capture.
- Castling with all path conditions (clear, duck-blocked, king-moved).
- Fowling detection after duck-induced stalemate.

5.3 REGRESSION TESTING
The 192-test suite is run as a pre-merge regression gate on the master branch.
No new stage training checkpoint is promoted unless all tests pass.

5.4 BOUNDARY & EDGE-CASE TESTING
Tests explicitly target boundary inputs:
- Board corners (0,0), (0,7), (7,0), (7,7)
- Sentinel values: duck_pos = (-1, -1), en_passant_target = None
- Out-of-bounds coordinates (negative, row/col 8+)
- Empty square operations (piece missing, no moves)

5.5 PROPERTY TESTING (ROUNDTRIP)
All (encode → decode) roundtrips for the full 64 × 64 action space are
verified to be bijective within the valid range [0, 4095].
