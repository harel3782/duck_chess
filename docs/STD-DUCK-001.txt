1. INTRODUCTION
================================================================================

This document specifies the individual test cases that implement the strategy
defined in STP-DUCK-001. Each test case maps to one or more test items and is
grounded in the actual source code of DuckChess_Game/Logic/. Test cases are
executable with: python -m pytest tests/ -v

Test identification scheme: TC-<MODULE>-<NNN>

Modules:
  BB  = BitboardManager
  RC  = RulesChecker
  MG  = MoveGeneration
  AM  = ActionMasker
  OE  = ObservationEncoder
  EG  = EndgameChecker
  MP  = MovePipeline
  GV  = GameStateValidator
  ENV = RL Environment

2.1 BITBOARDMANAGER (TI-01)
================================================================================

TC-BB-001: set_bit places single bit at corner a8 (sq=0)
  Preconditions:  Fresh empty BitboardManager
  Steps:          Call set_bit(0, 0)
  Expected:       get_bit(result, 0) is True; all other 63 bits are 0
  Postconditions: Bitboard = 1

TC-BB-002: set_bit places single bit at corner h1 (sq=63)
  Preconditions:  Fresh empty BitboardManager
  Steps:          Call set_bit(0, 63)
  Expected:       get_bit(result, 63) is True; all other bits are 0
  Postconditions: Bitboard = 2^63

TC-BB-003: clear_bit removes a previously set bit
  Preconditions:  Bitboard with bit 27 set
  Steps:          Call clear_bit(bitboard, 27)
  Expected:       get_bit(result, 27) is False; other set bits unchanged
  Postconditions: Bit 27 = 0

TC-BB-004: coords_to_square maps all four corners correctly
  Preconditions:  Any state
  Steps:          coords_to_square(0,0), (0,7), (7,0), (7,7)
  Expected:       Returns 0, 7, 56, 63 respectively
  Postconditions: No state change

TC-BB-005: add_piece sets white_occupancy bit
  Preconditions:  Fresh BitboardManager
  Steps:          add_piece('w', PAWN, 6, 0)
  Expected:       get_bit(white_occupancy, 48) is True; black_occupancy unchanged
  Postconditions: white_occupancy bit 48 = 1

TC-BB-006: add_piece for black does not set white_occupancy
  Preconditions:  Fresh BitboardManager
  Steps:          add_piece('b', PAWN, 1, 0)
  Expected:       get_bit(white_occupancy, 8) is False;
                  get_bit(black_occupancy, 8) is True
  Postconditions: Correct occupancy

TC-BB-007: remove_piece clears all occupancy
  Preconditions:  BitboardManager with one white pawn at (6,0)
  Steps:          remove_piece('w', PAWN, 6, 0)
  Expected:       white_occupancy == 0, all_occupancy == 0
  Postconditions: All bitboards zero

TC-BB-008: move_duck sets duck_board and does not affect occupancy
  Preconditions:  Fresh BitboardManager
  Steps:          move_duck(3, 3)
  Expected:       get_bit(duck_board, 27) is True; white_occupancy and
                  black_occupancy both 0
  Postconditions: Duck separated from occupancy

TC-BB-009: move_duck clears previous square
  Preconditions:  BitboardManager with duck at (3,3)
  Steps:          move_duck(4, 4)
  Expected:       get_bit(duck_board, 27) is False;
                  get_bit(duck_board, 36) is True
  Postconditions: Only bit 36 set

TC-BB-010: move_duck with (-1,-1) clears duck_board
  Preconditions:  BitboardManager with duck at any square
  Steps:          move_duck(-1, -1)
  Expected:       duck_board == 0
  Postconditions: No duck on board

TC-BB-011: verify_sync passes on starting position
  Preconditions:  HeadlessEngine after reset_game_state()
  Steps:          Call bb_mgr.verify_sync(board, duck_pos)
  Expected:       Returns True
  Postconditions: Sync confirmed

TC-BB-012: verify_sync fails when bb has extra piece not on 2D board
  Preconditions:  Starting position + manually set extra bit
  Steps:          Set extra pawn bit in bb_mgr, do not update 2D board

  Postconditions: Desync detected

TC-BB-013: verify_sync fails when duck_pos mismatches
