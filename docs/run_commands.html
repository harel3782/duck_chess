🦆 Duck Chess — Run & Training Commands
Every way to run the project: web UI, training pipelines, evaluation, and testing

Rule of thumb: Run all commands from the project root. SBThree scripts must be launched as modules with -m so package imports resolve. On Windows use the venv interpreter: .venv\Scripts\python.exe (shown as python below).

1 · Environment setup

Python 3.12 with a local .venv/. A GPU is not required — Torch runs on CPU. The engine is pure Python (no pygame).

Create / activate the virtual environment (PowerShell)

python -m venv .venv .venv\Scripts\Activate.ps1

Install all pinned dependencies — closes the known httpx/playwright gap so web-UI & perf tests can collect

pip install -r requirements.txt

Install Playwright browsers — only needed for the e2e / visual-regression test layer

playwright install

2 · Web UI the only front-end

FastAPI backend + single-file HTML/JS frontend under web_ui/, on port 7890. Loads MaskablePPO checkpoints on CPU; the opponent list is auto-discovered from models/duck_ppo/**/*.zip. Supports human-vs-AI, local 2-player, save/load, and replay.

Start the server (recommended) — then open http://127.0.0.1:7890

python -m uvicorn web_ui.server:app --port 7890

Alternative launch — runs directly; interactive API docs live at /docs

python web_ui/server.py

Auto-reload during development — restarts on source edits

python -m uvicorn web_ui.server:app --port 7890 --reload

How a turn works over the API

A Duck Chess turn is two phases, mirrored by the API: POST /api/move-piece then POST /api/place-duck, after which the model plays its full turn automatically.

EndpointPurpose
GET /api/modelsList auto-discovered opponent checkpoints
POST /api/new-gameStart a game (model: null ⇒ local 2-player)
POST /api/legal-movesLegal moves for the current phase
POST /api/move-piecePhase 1 — move a piece
POST /api/place-duckPhase 2 — place the duck (AI then replies)
POST /api/resign · /api/undo-move · /api/save-gameResign, undo, save
GET /api/saved-games · /api/load-game/{file}Browse & load replays
POST /api/delete-gameDelete a saved game
Note: Web saves are JSON under saved_replays/web/ (created on demand, git-ignored). Each half-move stores a {board, duck} snapshot so the duck moves during replay review. See docs/WEB_UI_SETUP.md.

3 · RL training — current line of work antiexploit_v2 → ExIt

The active pipeline lives on branch antiexploit_v2. Read PLAN_V2.md for the full rationale. It is a two-phase flow: a corrective policy run, then an Expert-Iteration loop.

Phase A — corrective policy run

train_antiexploit_v2 — fixes opening repetition, weak duck placement, and endgame collapse

python -m DuckChess_Game.SBThree.train_antiexploit_v2

Phase B — Expert Iteration (ExIt) loop

MCTS self-play → retrain policy+value → eval → repeat.

run_exit — the orchestrator that drives the whole gen→train→eval loop

python -m DuckChess_Game.SBThree.run_exit

gen_mcts_data — MCTS self-play data generator producing (obs, π, z) npz files (used by run_exit)

python -m DuckChess_Game.SBThree.gen_mcts_data

train_exit — a single joint policy+value training step

python -m DuckChess_Game.SBThree.train_exit

Unattended full build

run_full_build.ps1 — runs the whole build (Phase A then ExIt), writes its PID to logs/fullbuild.pid, logs progress to logs/antiexploit_v2_progress.csv

./scripts/run_full_build.ps1

6 · Testing

pytest.ini sets testpaths=tests. The engine + RL core is fast and headless.

Run the canonical suite

pytest

Run a single module (verbose)

pytest tests/test_rules_checker.py -v

Coverage report for the game engine → HTML

pytest --cov=DuckChess_Game.Logic --cov-report=html
Known status: tests/ collects ~400 tests; 3 web/perf files error at collection when httpx is missing (run pip install -r requirements.txt). The e2e & visual-regression tests need playwright install. Full breakdown in docs/TESTING.md.
